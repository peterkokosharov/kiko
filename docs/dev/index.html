1. Overview

kiko-proxy is a minimal FastAPI server that sits in front of the Anthropic, Google Gemini, and OpenAI APIs. It is designed for a single owner: there is one secret (MASTER_KEY), no user database, no JWT, and no enterprise middleware.

Clients authenticate with MASTER_KEY via any of three HTTP header conventions (x-api-key, Authorization: Bearer, or x-goog-api-key). After authentication, requests are translated to the appropriate upstream protocol through litellm, and every successful call is recorded to a local SQLite billing database at ~/.kircho/kircho.db.

A configurable monthly spending cap (monthly_cap_usd) returns protocol-correct 429 responses before any upstream call is made when the cap is reached. Model configuration lives in a YAML file and is optionally seeded into the SQLite models table, which becomes the runtime source of truth.

3. Request Handling Sequence

Every authenticated request passes through three layers before the upstream call: auth checks the master key, _prepare() strips dangerous client fields and injects server-side credentials, and the route handler calls litellm. After a successful response the billing logger writes to SQLite asynchronously. 

sequenceDiagram
    participant C as Client
    participant Auth as user_api_key_auth
    participant Prep as _prepare()
    participant Route as Route handler
    participant LLM as litellm / upstream
    participant Bill as KikoSQLiteLogger

    C->>Auth: POST /v1/messages\nx-api-key: MASTER_KEY
    Auth->>Auth: hmac.compare_digest(key, MASTER_KEY)
    alt invalid key
        Auth-->>C: 401 Unauthorized
    end
    Auth->>Route: UserAPIKeyAuth object
    Route->>Prep: request body
    Prep->>Prep: strip client api_key field
    Prep->>Prep: inject model litellm_params\n(api_key, api_base from config)
    Route->>LLM: litellm.acompletion(model, ...)
    LLM-->>Route: ModelResponse
    Route->>Bill: log_success_event(cost, tokens, route)
    Bill->>Bill: INSERT INTO billing\n(model, cost_usd, route)
    Route-->>C: response (streaming or full)

4. API Key Resolution

Model credentials in the YAML config can be literal strings or references to environment variables using the os.environ/VAR syntax. On Windows, if the environment variable is empty, kiko falls back to the Windows Credential Manager at target KIRCHO/VAR. 

flowchart TD
    V["yaml value"] --> Q{"matches\nos.environ/VAR?"}
    Q -- "No (literal)" --> LIT["return as-is\n⚠ hardcoded in yaml"]
    Q -- "Yes" --> ENV["os.environ.get(VAR)"]
    ENV --> E{"empty?"}
    E -- "No" --> RET["return env value"]
    E -- "Yes" --> WCM["_cred_get(VAR)\nWindows Credential Manager\ntarget: KIRCHO/VAR"]
    WCM --> W{"found?"}
    W -- "Yes" --> RWCM["return WCM value"]
    W -- "No" --> EMPTY["return ''"]
The Windows Credential Manager fallback is Windows-only. On Linux and macOS, _cred_get() always returns an empty string immediately (no WCM available). Use real environment variables on those platforms.

5. Supported Routes

All routes (except /health) require the MASTER_KEY. Streaming routes return text/event-stream.

Route Method Protocol Notes
/v1/messages POST Anthropic Messages streaming + non-stream
/v1/messages/count_tokens POST Anthropic local token count, no upstream call
/v1beta/models/{m}:generateContent POST Gemini non-stream; translated via google_genai adapter
/v1beta/models/{m}:streamGenerateContent POST Gemini SSE; no event: prefix, no [DONE] marker
/v1beta/models/{m}:countTokens POST Gemini local token count, no upstream call
/v1/responses POST OpenAI Responses Codex CLI; stream + non-stream; web_search stripped
/v1/chat/completions POST OpenAI Chat passthrough via litellm.acompletion

6. Model Alias Resolution

Before _prepare() runs, the client's model name is resolved through a two-priority alias chain. YAML glob patterns take precedence; environment-variable tier aliases (ANTHROPIC_DEFAULT_OPUS_MODEL etc.) apply as a fallback for claude-* models. The resolved alias is then looked up in the SQLite models table (or YAML fallback) to obtain litellm_params. 

flowchart TD
    REQ["client requests model alias\ne.g. 'claude'"] --> DB2[("kiko SQLite\nmodels table")]
    DB2 --> GLOB{"glob match?\ne.g. claude*"}
    GLOB -- "Yes" --> PARAMS["load litellm_params\n_resolve_env() on each value"]
    GLOB -- "No" --> YAML["fallback to\nkiko-sample.yaml model_list"]
    PARAMS --> LLM2["litellm.acompletion\n(model=provider/id, api_key=..., api_base=...)"]
    YAML --> LLM2

7. Billing Schema

The SQLite database at ~/.kircho/kircho.db (or KIKO_DB_PATH) contains two tables. The billing table records one row per successful upstream call. The models table stores model aliases and their routing parameters. 

erDiagram
    billing {
        integer id PK
        text model
        text route
        real cost_usd
        integer tokens_in
        integer tokens_out
        text ts
    }
    models {
        integer id PK
        text alias
        text provider
        text api_base
        text api_key_env
        integer enabled
        text status
        text last_check
    }

billing.route identifies the request origin: messages, gemini_generate, gemini_stream, responses, chat, etc. Use it to break down cost by client type via GROUP BY route.

models.status is set by kiko --discover (values: unknown, ok, error). Disabled models (enabled=0) are hidden from the server and --list-models.

8. Monthly Cap Flow

When monthly_cap_usd is set in general_settings, every route handler calls _check_monthly_cap() before touching the request body or making any upstream call. The cap is checked by summing the current calendar month's cost_usd from the billing table. 

flowchart TD
    REQ2["incoming request"] --> SUM["SELECT SUM(cost_usd)\nFROM billing\nWHERE ts >= month_start"]
    SUM --> CAP{"sum >= monthly_cap_usd?"}
    CAP -- "Yes" --> E429["return 429\nwith Anthropic / OpenAI / Gemini\nerror shape"]
    CAP -- "No" --> CONT["continue to upstream"]
The 429 response body shape depends on the route: Anthropic routes return {"type":"error","error":{"type":"rate_limit_error","message":"..."}}, Gemini routes return {"error":{"code":429,"status":"RESOURCE_EXHAUSTED"}}, and OpenAI routes return {"error":{"code":"monthly_cap_exceeded"}}.
