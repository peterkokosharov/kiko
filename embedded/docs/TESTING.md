# kiko embedded - Testing

Levels, from fastest to slowest. Real API keys are never used by agents or stored in the repository;
only the owner uses real keys, for fixture recording (Phase 0) and the real-router smoke test.

## 1. Unit tests (desktop)

- Built with CMake (`-DKIKO_TESTS=ON`), run with `ctest`. Plain C test harness in `tests/harness.h`
  (assert macros + runner, no external dependency).
- Presets: `debug` (`-O0 -g`), `asan` (`-fsanitize=address,undefined -fno-omit-frame-pointer`),
  `release` (`-Os`, same flags as the package).
- Two suites. **libkiko** (`libkiko/tests/`, built alone with `cmake -S libkiko`): `buf`/`str`, `json`
  helpers, HTTP request and response parsers, SSE encoder and parser, retry policy (fake clock, fixed
  rng), keystore file checks, posix helpers, token estimate; many cases ported from kikolib's
  `gateway/tests/kiko/test_kikolib_*.py` so both libraries agree. **kiko-wrt** (`tests/`): config
  validation, rate limiter, OpenAI<->Gemini translators (request, response, stream state machine, tools,
  thought-signature ids), error mapping and scrubbing.
- Build-alone test: CI copies `libkiko/` into an empty directory and builds + tests it there, proving it
  does not depend on any proxy file.
- Stream tests feed input split at every byte boundary (1-byte, 2-byte, random chunks) and require
  identical output.
- `scripts/check.sh` runs build + unit tests + secret scan; it is the gate for every merge.

## 2. Mock upstream server

`tests/mock_upstream.py` (Python standard library only; tests may use Python, the product may not).

- Endpoints: OpenAI `/v1/chat/completions` (stream and non-stream), Gemini
  `:generateContent` and `:streamGenerateContent?alt=sse`.
- Scenarios chosen per request header `X-Mock-Scenario` or `--scenario`: ok, tools, 400, 401, 429 with
  `Retry-After`, 500, slow first byte, stalled stream, stream cut in the middle, invalid JSON, huge body,
  slow reader (backpressure).
- Logs every received request (headers with key values masked, body) to a file the tests assert on,
  e.g. "the key header was set", "the upstream request was aborted after client disconnect".
- Optional TLS mode with a test CA (generated by `tests/certs/make.sh`) plus a self-signed and a
  wrong-hostname certificate for the TLS rejection tests.

Integration tests (`tests/integration/`) start the daemon with a test UCI dir (`--config-dir`) against the
mock and drive it with `curl`.

## 3. Contract tests (recorded responses)

- Phase 0 records real request/response pairs from OpenAI and Gemini (stream and non-stream, with and
  without tools, a blocked prompt, a max-tokens stop) with the owner's keys at home.
- A sanitizer script replaces keys, ids and personal text before anything is committed under
  `tests/fixtures/{openai,gemini}/`. `scripts/secret-scan.sh` (patterns `sk-`, `AIza`, `Bearer `, plus a
  list of the owner's key prefixes kept outside the repo) must be clean before each commit.
- The mock replays fixtures; the tests check that kiko-wrt's output equals the expected OpenAI-format
  output stored next to each fixture (field by field, ignoring `id`/`created`).
- Re-recording is repeated before each release to catch provider API drift.
- Client checks: an opencode config pointed at kiko-wrt (mock behind it) runs a scripted chat with a tool
  call; the other clients (rex, Layka, Sisi, Lassie) get a minimal scripted request each.

## 4. Fuzzing (desktop)

- libFuzzer targets (see TEAM.md checklist). libkiko, in `libkiko/fuzz/`: `fuzz_http_request`,
  `fuzz_http_response`, `fuzz_sse`, `fuzz_json`. kiko-wrt, in `fuzz/`: `fuzz_gemini_request`,
  `fuzz_gemini_response`, `fuzz_gemini_stream`, `fuzz_openai_rewrite`.
  Build: `cmake --preset fuzz` (clang, `-fsanitize=fuzzer,address,undefined`).
- AFL++ builds of the same targets for overnight runs (`afl-clang-fast`, persistent mode).
- Seed corpus from fixtures and unit-test inputs; JSON dictionary file for structure-aware mutation.
- Gate: 30 minutes per target clean on every change of a parser; overnight run before each tag.
  Crashes -> minimized input -> regression unit test.

## 5. OpenWrt in Docker

Images (exact tags checked on Docker Hub at the start of H1; placeholders below):

- Build: `openwrt/sdk:<target>-<version>` (e.g. x86-64 for 24.10 and 25.x).
- Run: `openwrt/rootfs:<target>-<version>` (x86-64).

Build the package with the SDK:

```sh
docker run --rm -v "$PWD:/src/kiko-wrt" openwrt/sdk:$SDK_TAG sh -c '
  ./scripts/feeds update base packages &&
  ./scripts/feeds install libubox libuclient libustream-mbedtls libjson-c libuci &&
  mkdir -p package/kiko-wrt && cp -r /src/kiko-wrt/openwrt/* package/kiko-wrt/ &&
  make defconfig && make package/kiko-wrt/compile V=s &&
  cp bin/packages/*/*/kiko-wrt* /src/kiko-wrt/dist/'
```

(The OpenWrt `Makefile` uses `PKG_SOURCE_PROTO` local/`USE_SOURCE_DIR` during development.)

Run it in the rootfs container:

```sh
docker run --rm -it -v "$PWD/dist:/pkgs" -v "$PWD/tests:/tests" -p 127.0.0.1:4000:4000 \
  openwrt/rootfs:$ROOTFS_TAG /bin/ash
# inside, 24.10 (opkg):
mkdir -p /var/lock && opkg update && opkg install /pkgs/kiko-wrt_*.ipk
# inside, 25.x (apk):
apk update && apk add --allow-untrusted /pkgs/kiko-wrt-*.apk
```

Inside the container the daemon is started either through procd (if the image's init runs; to be checked
in S9) or directly in the foreground (`kiko-wrt -f -c /etc/config`) with the mock upstream running on
the Docker host or in a sidecar container. Then:

- `curl` suite `tests/integration/curl_smoke.sh`: `/health`, `/v1/models`, non-stream and stream chat for
  one openai and one gemini model, a tool call round trip, 401/404/413/429 cases.
- Size: `ls -l /usr/bin/kiko-wrt`, package size from `opkg info` / `apk info -s`.
- Memory: `grep -E 'VmRSS|VmPeak' /proc/$(pidof kiko-wrt)/status` idle, then during 8 parallel streams
  (`tests/integration/load_streams.sh`), then 60 s after; RSS must return near idle (leak check).
- Logs: `logread | grep kiko-wrt` contains one line per request and no fake key strings.

## 6. Sanitizers and leak checks

- Whole unit + integration suite under the `asan` preset on desktop.
- valgrind `--leak-check=full --error-exitcode=1` for the integration suite (release build with `-g`).
- Soak: 2 hours of mixed requests against the mock, RSS sampled every minute, must stay flat.

## 7. Real-router smoke test (owner, before each tag)

On the owner's OpenWrt router (version and arch noted in the release notes):

1. Install the package (`opkg install` / `apk add`); `logread` shows a clean start, process runs as user
   `kiko-wrt`.
2. Key files in `/etc/kiko-wrt/keys/` are mode 0600; the daemon refuses to start with a 0644 key file.
3. Listens only on the LAN address (`netstat -lnt`); not reachable from WAN (test from a phone on mobile
   data).
4. `/v1/models` from a laptop lists the configured models; wrong token -> 401.
5. One real non-stream and one real stream chat per provider (OpenAI, Gemini) from `curl`.
6. One real tool-call round trip via opencode on Gemini and on OpenAI.
7. Each LAN client (rex, Layka, Sisi, Lassie, opencode) completes one real conversation.
8. Pull the WAN cable mid-stream: client gets an error event, daemon keeps running.
9. `uci set kiko-wrt.main.rate_rpm=2; uci commit; service kiko-wrt reload`; third request in a minute -> 429.
10. Idle RSS and binary size recorded; `logread` contains no key or token text.
11. `sysupgrade` backup includes `/etc/kiko-wrt/` (`sysupgrade -l | grep kiko-wrt`).
12. Reboot: service comes back on its own.
